# 회의록 — 지난 회의 이행 점검 (2026-07-14)

## 목적
새 회의를 시작할 때, **지난 회의에서 나온 액션아이템·안건이 실제로 수행됐는지**를 인원별로 한눈에 보고,
안 끝난 건을 **오늘 회의로 바로 넘겨** 흘리지 않게 한다. 완료 여부는 이미 일일계획표(`daily_tasks.done`)에 있으므로 자동 표시한다.

## 위치·동작
- 회의록 편집 화면(`renderMeetingEditor`)의 **안건 카드 바로 위**에 카드 하나 추가.
- 기본은 접힌 상태: **`📌 지난 회의 이행 점검`** 버튼 + 옆에 회의 선택 드롭다운.
- 버튼을 누르면(또는 드롭다운에서 회의 선택) 아래로 패널이 채워진다. (자동 아님)

## 불러올 회의
- 기본 = **가장 최근 회의**(지금 편집 중인 회의 제외). 편집 중이 아닌 신규면 전체에서 최신.
- 드롭다운(`meetingReviewSelect`)에 최근 회의 목록(제목·날짜, 최대 20개, 현재 회의 제외)을 담아 다른 회의도 선택 가능.

## 패널 구성 (`renderMeetingReviewPanel`)
1. 선택된 회의의 **액션아이템**(`meeting_actions`)을 담당자별 칸(칸반)으로.
   - 담당자 순서: `MEETING_ASSIGNEES` 중 항목이 있는 담당자만. 담당자 없는 항목은 "미지정" 칸.
   - 각 항목 상태:
     - **✅ 완료** — `daily_task_id` 있고 `daily_tasks.done = true`
     - **⬜ 미완료** — `daily_task_id` 있고 `done = false` (빨간 강조)
     - **⚠️ 미전송** — `daily_task_id` 없음 (일일계획표로 안 보낸 방치 건, 빨간 강조)
   - 완료 항목도 표시하되 흐리게, 미완료/미전송은 강조.
2. 선택된 회의의 **미완료 안건**(`agenda` 중 `done=false`)을 담당자 없이 별도 줄로. (안건은 담당자가 없음)
3. **미완료·미전송 항목 + 미완료 안건**에 `[오늘로↗]` 버튼.

## "오늘로 넘기기" (핵심)
- `[오늘로↗]` → 현재 회의 액션아이템 배열 `_meetingActions`에 새 항목 추가:
  `{ id:null, task:<항목 내용>, assignee:<지난 담당자 또는 ''>, dueDate:'', dailyTaskId:null }`
  → `renderMeetingActions()` 재렌더. (아직 저장·전송 안 함 — 사용자가 검토 후 저장/전송)
- 같은 항목을 이미 넘겼으면(같은 task+assignee가 `_meetingActions`에 있으면) 버튼 비활성화("추가됨").
- 넘기면 `_meetingDirty = true`.

## 데이터 로드 (`loadMeetingReviewData(meetingId)`)
1. `meeting_actions`에서 그 회의의 `id, task, assignee, daily_task_id` 로드.
2. `daily_task_id`가 있는 것들의 `daily_tasks.done`을 한 번에 조회(`.in('id', ids)`)해 완료 여부 맵.
3. `meetings`에서 그 회의의 `agenda`(jsonb) 로드(이미 편집 화면 진입 시 목록에 있을 수도 있으나, 안전하게 조회).

## 상태 변수
- `_meetingReviewId` — 현재 점검 패널이 보고 있는 지난 회의 id (없으면 미표시).

## UI (스타일)
- 카드 헤더: 버튼 + 드롭다운.
- 칸반: `.mrv-board`(가로 스크롤), `.mrv-col`(담당자별), `.mrv-item`(항목) — 완료/미완료/미전송 색 구분.
- `[오늘로↗]`: 작은 버튼.

## 범위 밖 (이번에 안 함)
- 지난 회의에서 직접 완료 체크(완료 원본은 일일계획표).
- 여러 회의를 동시에 겹쳐 보기(한 번에 한 회의만).
- 안건 항목의 담당자 지정(안건은 담당자 개념 없음 — 그대로 유지).

## 검증
- `node --check app.js`
- 브라우저: 지난 회의 액션아이템이 담당자별로, 완료/미완료/미전송이 올바르게, `[오늘로↗]`가 `_meetingActions`에 정확히 추가되는지(중복 방지 포함).
- 다크모드·콘솔 오류 없음.
